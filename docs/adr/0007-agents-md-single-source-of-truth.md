# 7. AGENTS.md is the single source of truth for agent instructions

## Status

Accepted

## Context

The repository is worked on by several AI coding agents (Claude Code, OpenCode,
GitHub Copilot, and — as of this ADR — OpenAI Codex and Google Gemini CLI). Each
agent has its own convention for where it looks for project-level instructions.
Without a deliberate strategy, the same guidance gets copied into a Claude file, a
Gemini file, a Cursor file, and so on — and the copies drift.

Two facts shape the decision:

1. By 2026 the `AGENTS.md` convention is read **natively at the repository root**
   by most agents (Codex, Jules, Cursor, Windsurf, Roo Code, Zed, JetBrains Junie,
   Aider, Amp, and Copilot). A few do not: Gemini CLI reads `.gemini/settings.json`
   `context.fileName`; Cline/Continue read a `*-rules/` directory of plain markdown.
2. This harness is generated by a Copier template
   (`gh:grAItools/harness-copier-template`, see `.copier-answers.yml`) with
   per-agent toggles. Net-new agent wiring is therefore a template concern as much
   as a per-repo one.

## Decision

Root **`AGENTS.md` is the single source of truth** for agent instructions. Every
other agent is wired to it **by reference, never by duplicating content**:

- **Native** — agents that read root `AGENTS.md` directly get nothing extra.
- **Symlink** — when an agent reads a plain-markdown file at a fixed path with no
  required frontmatter, point it there with a filesystem symlink to `AGENTS.md`
  (matching the existing `.claude/` / `.opencode/` → `.agents/` symlink convention).
- **Stub** — when an agent needs a config shape a symlink cannot satisfy (a JSON
  key, or a frontmatter'd file), add a thin pointer/config stub that references
  `AGENTS.md`. The precedent is `.github/copilot-instructions.md`.

Tool-specific guidance that does **not** belong to every agent stays in that tool's
own file — e.g. Claude-only notes live in `CLAUDE.md` (whose first line is the
`@AGENTS.md` import), never in `AGENTS.md`.

The destructive-command deny-list is canonicalized in
`.agents/hooks/block-destructive.sh`. Claude Code's `PreToolUse` hook calls it;
OpenCode's declarative `permission.bash` deny-list cannot call a script, so it is a
**documented hand-kept mirror** of that script — not independent policy.

The current supported-agent matrix and the recipe for adding a new agent live in
`.agents/README.md`.

## Consequences

- Instruction content exists in exactly one place; agents are added by adding a
  link/stub, not by copying prose. Drift between agents is structurally prevented.
- Adding Codex required no file (it reads `AGENTS.md` natively); adding Gemini CLI
  required only a one-line `.gemini/settings.json` stub.
- `AGENTS.md` must stay lean — it is consumed by every agent's context budget and by
  Codex's 32 KiB doc cap. The existing "≤ ~200 lines" rule is now load-bearing.
- The OpenCode deny-list is a mirror, not a second source of truth; a future CI
  check could assert it is a superset of the script's patterns.
- Because the primary config files (`.claude/settings.json`,
  `.opencode/opencode.jsonc`, `AGENTS.md`, the managed `.gitignore` block) are
  Copier-managed, edits to them should also be ported upstream to the template
  behind toggles (e.g. `gemini`, `codex`); otherwise `copier update` can revert
  them. Net-new files (`.gemini/settings.json`, `.agents/hooks/*`,
  `.agents/README.md`, this ADR) are not at risk.
- Symlink-based wiring depends on `core.symlinks=true`; on Windows checkouts without
  it, prefer a stub. This is documented centrally in `.agents/README.md`.
